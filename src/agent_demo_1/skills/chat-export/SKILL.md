# Chat Export：聊天记录导出

## 1. 目标

将当前会话中可访问的聊天记录整理为结构化 JSON 数据，并通过 `scripts/export_chat.py` 将其导出为 Markdown（`.md`）文件，供用户阅读、保存、归档或下载。

导出应遵循以下原则：

- **内容忠实**：保留原始消息内容，不擅自总结、改写或删除有效信息。
- **顺序一致**：按照消息在对话中出现的先后顺序导出。
- **格式规范**：使用合法的 JSON 作为脚本输入，最终生成 Markdown 文件。
- **范围明确**：仅导出当前会话中实际可访问的聊天记录，不声称能够获取不可访问的历史消息。
- **结果可验证**：确认文件生成成功后，才向用户提供下载链接。

## 2. 触发条件

### 应执行导出

用户明确提出以下任一需求时，执行导出流程：

- 导出聊天记录、对话历史或当前会话。
- 将聊天记录保存为 Markdown、MD 文件。
- 生成当前聊天的下载文件或备份文件。
- 将整个对话整理成文件，方便本地保存。
- 在上下文明确的情况下，用户通过“帮我导出”“保存这段聊天”等简短表达提出导出要求。

### 不应执行导出

以下情况仅提供说明，不生成文件：

- 用户只询问如何实现聊天导出功能。
- 用户只询问如何安装、配置或使用本 Skill。
- 用户仅要求总结、翻译、润色或分析聊天内容，而没有要求导出文件。
- 用户只要求生成一份与当前聊天记录无关的 Markdown 文档。

如果用户只要求导出某一段对话、指定角色的消息或特定时间范围，应优先遵循用户指定的范围。

## 3. 导出流程

必须按以下顺序执行。

### 步骤一：确定导出范围

1. 默认导出当前会话中可访问的完整对话。
2. 如果用户指定了消息范围、主题、时间段或角色，则按照指定条件筛选。
3. 保留原始消息的先后顺序。
4. 不得虚构缺失的消息，也不得声称已导出无法访问的历史记录。
5. 如果无法确认用户要求的范围，且不同解释会显著影响导出结果，则先向用户确认。

默认纳入用户与助手之间实际发生的对话。对于工具调用、工具返回结果和其他辅助消息，只有在它们属于用户要求的导出范围、且具有可访问并适合导出的内容时，才按需纳入。

不得导出隐藏的系统指令、开发者指令、内部推理或其他非用户可见的内部信息。

### 步骤二：整理为 JSON

将消息转换为 JSON 数组，作为下一个步骤的输入，每条消息包含 `role` 和 `content` 两个字段。

标准结构：

```json
[
  {
    "role": "user",
    "content": "你好"
  },
  {
    "role": "assistant",
    "content": "你好！有什么可以帮你？"
  }
]
```

格式要求：

- `role` 使用原始消息对应的角色标识；常规对话使用 `user` 和 `assistant`。
- `content` 保存消息的原始文本内容。
- 消息必须按原始对话顺序排列。
- 使用标准 JSON 转义规则处理引号、反斜杠和换行符。
- 使用 UTF-8 编码，完整保留中文及其他 Unicode 字符。
- 不得在 JSON 数据前后添加说明文字、Markdown 代码围栏或其他非 JSON 内容。
- 不得因为消息较长而擅自截断内容。

对于多模态消息：

- 如果可以访问文本内容，则保留可访问的文本。
- 如果存在图片、音频、视频或文件附件，且运行环境能够提供其引用信息，可按脚本支持的格式记录附件引用或简明占位说明。
- 不得将无法访问的附件内容描述为已读取或已完整导出。
- 如果现有脚本仅支持纯文本，应遵循脚本实际支持的输入格式，并在最终回复中说明适用的限制。

### 步骤三：运行导出脚本

1. 执行导出命令：
```sh
python3 scripts/export_chat.py --input "聊天记录 JSON 数组"
```

2. 脚本执行成功后会返回：
```json
{
  files: [
    {
      "file_name": "文件名称",
      "url": "文件下载地址"
    }
  ]
}
```
